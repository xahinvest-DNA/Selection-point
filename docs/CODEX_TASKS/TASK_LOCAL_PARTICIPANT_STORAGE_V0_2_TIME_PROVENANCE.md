# TASK — Local Participant Storage v0.2 / Time Provenance

**Status:** ACTIVE / explicitly authorized follow-up to v0.1  
**Scope:** narrow data-provenance patch only  
**Do not open:** Stage 5, SP-LAB-002, new methodology, app/product scope

## 1. Reason

In the real micropilot, participants may submit their evening D1 report on the correct day, while the owner may transfer it into the local store one or more days later.

The storage layer must not confuse:

- the day the report describes;
- when the participant submitted/sent the report, if known;
- when the record was ingested into the local store.

This distinction is required so owner forwarding delay cannot be misread as participant measurement/adherence delay.

## 2. Required D1 time fields

Keep the existing `date` as the participant report/event date.

Add:

```yaml
time_provenance:
  participant_submitted_at_local: null
  participant_timezone: null
  ingested_at_utc: <auto-generated by CLI>
```

Rules:

- `date` remains authoritative for trajectory placement;
- `participant_submitted_at_local` is optional and may be null if exact source timestamp was not captured;
- never infer a submission time;
- `participant_timezone` may be null if not known;
- `ingested_at_utc` MUST be generated automatically by the storage CLI at write time;
- editing/importing later must never alter the original report date;
- delayed owner ingestion is not participant non-adherence.

## 3. Audit behavior

For `add-daily`:

- record the ingestion timestamp in the stored raw record or immutable companion metadata;
- on explicit overwrite/revision, preserve the original ingestion provenance and append revision timestamp/audit data rather than silently replacing provenance.

## 4. Weekly review input

The generated weekly review bundle must expose at least:

- `date`;
- `participant_submitted_at_local` when observed;
- `ingested_at_utc`.

Any future adherence analysis must use participant submission time only when actually observed. Ingestion time must not be substituted for it.

## 5. Tests

Add tests for:

1. delayed ingestion preserves the supplied report `date`;
2. `ingested_at_utc` is auto-populated;
3. missing participant submission time remains null/unknown;
4. no participant submission time is inferred from ingestion time;
5. weekly review bundle preserves time provenance;
6. revision/overwrite does not silently destroy original provenance.

## 6. Documentation

Update the operator guide with the rule:

> Participant report date and local ingestion date are different facts. If the owner enters a report later, use the date the participant reported for; the CLI records ingestion time separately.
