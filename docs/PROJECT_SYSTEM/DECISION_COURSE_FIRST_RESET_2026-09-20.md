# Decision — Return to Course-First Development

**ID:** SP-DEC-COURSE-FIRST-RESET-001  
**Date:** 20 September 2026  
**Status:** approved by Owner directive  
**Scope:** active project direction

## 1. Trigger

Owner identified a critical project drift:

> The project moved away from the original task of creating an effective educational course for Stage 1 and became dominated by Gate progression, validation architecture, questionnaires and evidence-management work.

The Owner explicitly directed the project to return to the point before the Gate trajectory became the active development path.

## 2. Exact pivot

The Gate-based training-development trajectory was introduced in commit:

`30601cb7a4deef9cdd8fa64595d334c631afaaaf — Approve SP work operating model`

Its parent is:

`59b705d8362c9c7c7be4690e805093a26fdb758f`

The parent state is the semantic reference point for the reset.

The reset is **not** a destructive git rollback. Later research is preserved for possible reuse, but the Gate pipeline no longer defines the active course-development route.

## 3. Active objective

The active objective is restored to:

> **Create an effective teachable course for Selection Point Stage 1.**

The course must answer, in learner-facing terms:

- what the first stage means;
- what the learner needs to understand;
- what the learner needs to notice in ordinary life;
- what practical exercises teach the capability;
- how the material is sequenced so that it is understandable and usable;
- how the learner gets real feedback from practice;
- what common misunderstandings and traps must be handled.

The course itself is the current product-development object.

## 4. What stops now

The following are suspended as active work:

- Gate progression as the main project route;
- post-protocol validation V0;
- optimization/modification of questionnaires;
- questionnaire architecture as a prerequisite for course creation;
- evidence-packet production for the purpose of closing training Gates;
- Stage 1 validation design as the next active task.

No further participant-data collection is required for current course development.

## 5. Status of Gate-era artifacts

Gate-era artifacts are preserved as:

> **research/reference material**

They may contain useful distinctions, literature synthesis, practice ideas and Red Team constraints.

They do **not** control the sequence of course development.

In particular, useful content may be selectively reused from:

- Stage 1 Capability Spec;
- Stage 1 Research Packet;
- Psychological Mechanism Map;
- Automaticity research;
- Learning Units;
- Practice Protocol;
- Measurement Reactivity observations;
- Red Team critiques.

Reuse requires a course-design reason, not Gate compliance.

## 6. Questionnaire boundary

The questionnaire is not a current development target.

At this stage:

```text
course development
≠ questionnaire development
```

A questionnaire may later be created or adapted only if the finished course needs a simple feedback instrument.

## 7. Research role

Research remains important, but its function changes.

Research should now answer concrete course questions, for example:

- What does a learner need to understand before a practice makes sense?
- Which psychological distinctions are actually trainable?
- Which exercises have evidence behind them?
- What creates resistance or overload?
- How can practice produce real-world feedback quickly?
- Which metaphors/explanations illuminate rather than distort?

Research serves teaching design.

Teaching design no longer serves a Gate process.

## 8. Active development rule

The working loop becomes:

```text
Stage 1 meaning
→ learner problem
→ teaching objective
→ explanation
→ exercise
→ lived feedback
→ revision of the lesson/course
```

not:

```text
Gate artifact
→ Gate review
→ Gate closure
→ next Gate
```

## 9. Next deliverable

Create the Stage 1 course itself, beginning with:

`docs/COURSE/STAGE_1_COURSE_WORK_BRIEF.md`

Then develop learner-facing course material directly.

## 10. Boundaries preserved

This reset does not alter approved Foundation meaning.

The following remain intact:

- the five-stage architecture;
- RC-018;
- approved Stage 1–4 Foundation work;
- reality/falsification principle;
- distinction between internal choice and realized continuation.

Only the **development route for the educational course** is changed.
