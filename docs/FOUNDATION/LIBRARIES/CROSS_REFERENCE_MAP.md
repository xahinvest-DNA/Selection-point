## Сквозная последовательность


## Системный предохранитель

SP-S3-P13:

> **Модель остаётся рабочей только пока реальность сохраняет возможность её изменить.**

Этот принцип проходит через всю S4: ни навык, ни рабочая модель, ни self-модель, ни выбранная задача, ни конкретный ход, ни прежняя жизненная форма, ни локальная интерпретация серии событий не получают иммунитета от фактической позиции.

RC-018 добавляет ещё один предохранитель:

> **Внутренний выбор не получает статус фактически совершённого хода только потому, что он был искренне принят.**

```text
selected continuation
≠ realized continuation
```

## RC-018 и Human Change Model

RC-018 не создаёт SP-HCM-10. Он уточняет переходы между уже утверждёнными положениями.

```text
HCM-04:
образ себя / сценарий участвуют в выборе

→ choice point
→ selected continuation

RC-018:
selected continuation
≠ automatically realized continuation

→ HCM-05:
реально произошедшее продолжение
изменяет ситуацию и действующего человека

→ HCM-06:
последствия
≠ automatically used feedback

→ HCM-08:
новая сборка формируется повторяемыми
фактически развернувшимися циклами
```

Поэтому core cycle теперь читается так:

```text
позиция
→ выбор
→ выбранное продолжение
→ фактически реализованное продолжение
→ последствия
→ feedback
→ новая позиция
```

### P07 — zero-delta

Проверенные кандидаты распределились по уже существующим слоям или оказались общечеловеческими, а не S4-specific.

```text
сильная боль возможна
≠ отдельная структурная боль S4 обязательна
```

### P08

```text
P01 + P05 + P06 + S3-P08
→ восстановление участия
из фактической доступности
```

P08 отвечает не за предотвращение любого срыва, а за повторный вход в цикл выбора.

RC-018 уточняет:

> **Возвращение выбора ещё не считается реализованным изменением продолжения, пока выбранный ход не получил фактическую форму.**

### P09 — amended zero-delta

```text
S1-P09 + S3-P09 + HCM-02
→ тело уже является частью причинного контура

P09 reanalysis:
body-state bidirectionality
= сквозное свойство
≠ отдельная S4-specific телесная дельта
```

Intentional bodily leverage перенесён в функциональный слой P11, но телесная регуляция не считается эквивалентом восстановления выбора.

## Связи P10–P13

### P10 — жизненная форма и траектория

```text
P04:
релевантный приоритет может сохраняться / пересматриваться

P05:
направление не равно одному обязательному ходу

P08:
участие может восстановиться из неполной доступности

P10:
несколько фактически реализованных ходов
→ меняют распределение ресурсов / ролей / обязательств
→ создают новую фактическую жизненную форму
```

Главная вертикаль:

```text
S1-P10:
текущая жизнь как накопленная позиция

S2-P10:
разные обстоятельства — знакомая функциональная позиция

S3-P10:
собственная линия начинает оставлять материальный след

S4-P10:
устойчивость линии
не требует неизменности её прежней формы
```

### P11 — практики под нагрузкой

```text
P08 recovery
+ P09 body/state as available entry
+ P10 trajectory flexibility
+ RC-018 execution boundary
→ P11:
тренировать reality-coupled цикл выбора под нагрузкой,
а не отдельную технику снятия нагрузки
```

Функциональные классы:

```text
load recognition
→ relevant reorientation
→ graded/context-relevant load
→ available entry
→ selected functional move
→ realized continuation
→ reality-coupled consequences / feedback
→ recovery / re-entry
```

### P12 — критерии перехода

```text
P06:
нет гарантии будущей доступности
+
P08/P11:
re-entry является частью способности
→ P12:
readiness = не безошибочность,
а достаточно надёжное сохранение + functional re-entry
```

Ключевая граница:

> **Re-entry должен изменить ещё доступное продолжение.**

RC-018 делает эту формулу строже:

> **Изменение продолжения проверяется по тому, что фактически произошло, а не только по внутренне выбранному ходу.**

P12 открывает следующий уровень задачи:

```text
S4:
как сохранить / восстановить участие внутри нагрузки?

S5 boundary:
почему система условий снова и снова формирует сходные позиции?
```

### P13 — ловушка временного масштаба

P13 связывает P08, P10, P11 и P12 в новый предохранитель:

```text
P08/P11:
каждый момент может получить functional re-entry

P12:
отдельное выпадение не отменяет освоение

но

P13:
серия функционально сходных эпизодов
может стать новой фактической позицией
и обязана иметь право изменить macro-model
```

Главная формула:

> **Выбор совершается в моменте. Траектория обнаруживается во времени.**

Корректировка:

> **Прошлое не должно определять следующий выбор, но релевантная история должна иметь право изменить описание текущей позиции.**

RC-018 уточняет, какие данные входят в trajectory reading:

```text
series of selected continuations
≠ automatically
series of realized continuations
```

> **Внутренние выборы показывают направление намерения; фактически реализованные продолжения участвуют в построении фактической траектории.**

Дельта P12 → P13:

```text
P12:
не превращать отдельный lapse в приговор

P13:
не превращать каждый новый момент
в амнезию относительно accumulated trajectory feedback
```

P13 также соединяется с HCM-06/HCM-08 и RC-018:

```text
realized continuations
→ consequences
→ feedback
→ repeated cycles
→ trajectory-level data
```

## Граница S4 → S5

После P13 + RC-018 граница формулируется так:

```text
micro-scale:
что происходит сейчас?
→ что выбрано?
→ что фактически реализовано?

macro-scale:
что последние многие реализованные «сейчас»
вместе говорят о trajectory?
→ какие generating conditions стали проверяемой гипотезой?
```

Это не готовая архитектура S5.

Рабочие source distinctions:

- SP-SRC-023: `усилие действия ≠ усилие компенсации структуры`;
- SP-SRC-024: self-work может компенсировать неизменённую структуру;
- SP-SRC-025: moment-level correctness может скрыть trajectory-level drift;
- SP-SRC-028: selected continuation ≠ realized continuation.

## Матрица 5 × 13

Одинаковый P-номер разных ступеней не гарантирует новую дельту.

```text
есть practically useful distinction?
├─ да → самостоятельная delta
├─ нет → zero-delta
└─ каркас мешает → предложить пересмотр
```

P07 и P09 подтвердили допустимость `zero-delta`; P10–P13 подтвердили самостоятельные stage-specific различения. RC-018 показывает, что practically useful дельта может быть сквозной и не обязана становиться новым параметром матрицы.
