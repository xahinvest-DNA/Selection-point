## Системный предохранитель

SP-S3-P13:

> **Модель остаётся рабочей только пока реальность сохраняет возможность её изменить.**

Этот принцип проходит через всю S4: ни навык, ни рабочая модель, ни self-модель, ни выбранная задача, ни конкретный ход, ни прежняя жизненная форма, ни локальная интерпретация серии событий не получают иммунитета от фактической позиции.

## Связи P10–P13

### P10 — жизненная форма и траектория

```text
P04:
релевантный приоритет может сохраняться / пересматриваться

P05:
направление не равно одному обязательному ходу

P08:
участие может восстановиться из неполной доступности

P10:
несколько таких ходов
→ меняют распределение ресурсов / ролей / обязательств
→ создают новую фактическую жизненную форму
```

Главная вертикаль:

```text
S1-P10:
текущая жизнь как накопленная позиция

S2-P10:
разные обстоятельства — знакомая функциональная позиция

S3-P10:
собственная линия начинает оставлять материальный след

S4-P10:
устойчивость линии
не требует неизменности её прежней формы
```

### P11 — практики под нагрузкой

```text
P08 recovery
+ P09 body/state as available entry
+ P10 trajectory flexibility
→ P11:
тренировать reality-coupled цикл выбора под нагрузкой,
а не отдельную технику снятия нагрузки
```

Функциональные классы:

```text
load recognition
→ relevant reorientation
→ graded/context-relevant load
→ available entry
→ functional move
→ reality-coupled feedback
→ recovery / re-entry
```

### P12 — критерии перехода

```text
P06:
нет гарантии будущей доступности
+
P08/P11:
re-entry является частью способности
→ P12:
readiness = не безошибочность,
а достаточно надёжное сохранение + functional re-entry
```

Ключевая граница:

> **Re-entry должен изменить ещё доступное продолжение.**

P12 открывает следующий уровень задачи:

```text
S4:
как сохранить / восстановить участие внутри нагрузки?

S5 boundary:
почему система условий снова и снова формирует сходные позиции?
```

### P13 — ловушка временного масштаба

P13 связывает P08, P10, P11 и P12 в новый предохранитель:

```text
P08/P11:
каждый момент может получить functional re-entry

P12:
отдельное выпадение не отменяет освоение

но

P13:
серия функционально сходных эпизодов
может стать новой фактической позицией
и обязана иметь право изменить macro-model
```

Главная формула:

> **Выбор совершается в моменте. Траектория обнаруживается во времени.**

Корректировка:

> **Прошлое не должно определять следующий выбор, но релевантная история должна иметь право изменить описание текущей позиции.**

Дельта P12 → P13:

```text
P12:
не превращать отдельный lapse в приговор

P13:
не превращать каждый новый момент
в амнезию относительно accumulated trajectory feedback
```

P13 также соединяется с HCM-06/HCM-08:

```text
HCM-06 feedback
+ HCM-08 repeated cycles
→ feedback должен работать не только внутри эпизода,
но и на practically relevant временном масштабе серии
```

## Граница S4 → S5

После P13 граница формулируется так:

```text
micro-scale:
что происходит сейчас?
→ какой выбор доступен?

macro-scale:
что последние многие «сейчас» вместе говорят о trajectory?
→ какие generating conditions стали проверяемой гипотезой?
```

Это не готовая архитектура S5.

Рабочие source distinctions:

- SP-SRC-023: `усилие действия ≠ усилие компенсации структуры`;
- SP-SRC-024: self-work может компенсировать неизменённую структуру;
- SP-SRC-025: moment-level correctness может скрыть trajectory-level drift.
