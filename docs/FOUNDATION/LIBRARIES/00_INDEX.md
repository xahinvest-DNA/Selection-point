## Delta-first

После каждого нового утверждённого параметра большие общие реестры **не переписываются автоматически**.

Сначала создаётся parameter delta:

```text
новый claim
+ evidence questions
+ cross-reference
+ только реально новые terms / risks / visual decisions
```

Плановая консолидация больших реестров выполняется:

- после P05;
- после P10;
- после P13;
- на границе ступени;
- либо по отдельному решению Андрея.

28 августа 2026 года выполнена внеплановая governance-консолидация через SP-S4-P02. SP-S4-P03 и SP-S4-P04 хранятся как local delta до плановой консолидации после P05.

```text

≠

под нагрузкой

организующий приоритет
≠ оперативный приоритет

≠ state-driven displacement
```

Главная формула P04:

> **Под нагрузкой важна не неизменность задачи, а сохранение её осознанного места в иерархии решений.**
