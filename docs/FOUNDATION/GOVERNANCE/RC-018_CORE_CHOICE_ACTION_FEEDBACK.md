# RC-018 — Reality Check: выбор → реализованное продолжение → последствия → обратная связь

**Дата:** 15 сентября 2026 года  
**Объект:** сквозное уточнение ядра Selection Point  
**Статус:** reality-check-complete; red-team-complete; owner-approval-pending  
**Architect pass:** `CORE_CHOICE_ACTION_FEEDBACK_ARCHITECT_PASS_NOTES.md`  
**Source material:** `../SOURCE_MATERIALS/28_2026-09-15_CHOICE_ACTION_EXECUTION_FEEDBACK_BOUNDARY.md`

## 1. Проверяемый кандидат

> **Внутренне выбранное продолжение и фактически реализованное продолжение должны различаться. Неисполненный выбор не может получать внешнюю обратную связь как будто соответствующее действие произошло; вместо этого данные относятся к фактическому продолжению и, при несовпадении, к разрыву выбор → реализация.**

Короткая формула:

> **Выбрать ≠ сделать. Сделать ≠ получить желаемое. Последствия ≠ автоматически использованная обратная связь.**

## 2. Observability

Различение можно проверять без языка Selection Point, если prospectively или близко к моменту события фиксировать:

1. какое продолжение человек реально выбрал;
2. что фактически произошло;
3. было ли исполнение полным, частичным, заменённым другим действием или отсутствовало;
4. какие последствия последовали за фактическим продолжением;
5. какие выводы были использованы в следующем цикле.

```text
selected continuation = X
realized continuation = X / Y / partial X / withheld action
→ consequences
→ used feedback
```

## 3. Discriminability

Нужно различать:

```text
желание / goal intention
≠ выбранное продолжение
≠ фактически реализованное продолжение
≠ outcome
≠ использованная обратная связь
```

HCM-06 уже различает последствия и feedback; новая boundary добавляет отдельное различение между выбором и реализацией.

## 4. External compatibility

### Intention–behavior gap

Даже сильные intentions не гарантируют последующее действие; implementation intentions помогают сокращать этот разрыв.

Источники:
- https://pmc.ncbi.nlm.nih.gov/articles/PMC4500900/
- https://pmc.ncbi.nlm.nih.gov/articles/PMC9386038/

### Rubicon Model / action phases

Модель различает выбор цели, подготовку и actional phase, где намерение реализуется.

Источники:
- https://pmc.ncbi.nlm.nih.gov/articles/PMC9643924/
- https://pmc.ncbi.nlm.nih.gov/articles/PMC11578820/

### Implementation intentions

If–then planning повышает вероятность goal-directed behavior именно потому, что между намерением и запуском действия существует отдельная задача реализации.

Источники:
- https://pmc.ncbi.nlm.nih.gov/articles/PMC4500900/
- https://pmc.ncbi.nlm.nih.gov/articles/PMC8149892/

### Feedback и последствия

Feedback literature связывает последующую коррекцию с информацией о фактической практике / поведении и её результате, а не только с намерением.

Источники:
- https://pmc.ncbi.nlm.nih.gov/articles/PMC3303967/
- https://pmc.ncbi.nlm.nih.gov/articles/PMC5400271/

### Delayed / noisy consequences

При задержанных и распределённых последствиях возникает temporal credit assignment problem: реализованное действие делает feedback возможным, но не гарантирует однозначного causal вывода.

Источник:
- https://pmc.ncbi.nlm.nih.gov/articles/PMC4309984/

## 5. Альтернативные объяснения selected ≠ realized

Несовпадение не означает автоматически дефицит саморегуляции. Возможны:

- новые факты и сознательный пересмотр решения;
- объективная невозможность;
- внешнее ограничение;
- изменение приоритета;
- ретроспективная реконструкция «я выбрал»;
- слишком абстрактный исходный выбор;
- рационально достаточное частичное исполнение.

```text
selected ≠ realized
≠ автоматически weakness / sabotage / automatism
```

## 6. Обязательные ограничения

Внутренний выбор сам может менять состояние и внимание; запрещена формула `не сделал → ничего не произошло`.

Сознательно выдержанное невмешательство является реализованным продолжением.

Частичное исполнение даёт только частичную проверку.

Хороший / плохой outcome не является чистой оценкой качества хода.

## 7. Falsifiability

Уточнение следует отклонить или сузить, если:

1. selected и realized continuation нельзя prospectively различить;
2. различение не меняет диагностику, следующий вопрос или фиксацию;
3. оно создаёт action bias;
4. сознательная пауза ошибочно считается неисполнением;
5. внутренний выбор обесценивается как «нереальный»;
6. любой gap автоматически становится «саботажем»;
7. feedback приписывается одному действию при явно многопричинном / задержанном результате.

## 8. Practical consequence

Вместо одного вопроса `Что ты выбрал?` нужны отдельные:

```text
Что ты выбрал?
→ Что фактически произошло?
→ Где выбранное и реализованное совпали / разошлись?
→ Какие последствия относятся к реально произошедшему?
→ Что из этого стало feedback для следующего цикла?
```

## 9. Reality Check verdict

Статусы:

- `externally-compatible`;
- `externally-limited`;
- `pilot-observability-pending`;
- `falsifier-defined`;
- `owner-approval-pending`.

Reality Check поддерживает само различение, но не требует нового HCM-10.

Наиболее экономная версия:

> **Selection Point должен явно различать выбранное и фактически реализованное продолжение. Реальность даёт последствия относительно того, что фактически произошло; неисполненный выбор остаётся данными о намерении и процессе исполнения, но не заменяет проверку неслучившегося действия.**

После Red Team кандидат ожидает явного решения владельца.
