## 3. Предварительная рабочая граница P12

Рабочий кандидат:

> **Переход не требует отсутствия выпадений. Способность должна иногда сохраняться непосредственно внутри значимой нагрузки, а после выпадения — становиться повторяемо восстанавливаемой из изменившейся фактической позиции.**

Предварительно необходимы обе функции:

```text
сохранение
+
re-entry
```

При этом:

```text
спокойствие ≠ освоение S4
отсутствие ошибок ≠ освоение S4
хороший внешний результат ≠ освоение S4
быстрое восстановление ≠ универсальный критерий зрелости
```

## 4. Предварительная граница S4 → S5

S4:

> **Как сохранить или восстановить участие, когда система уже произвела нагрузку?**

S5:

> **Как изменить систему условий, которая регулярно формирует позиции, требующие такого восстановления?**

Рабочая формула:

```text
S4 = сохранять / восстанавливать участие внутри нагрузки
S5 = изменять систему условий, формирующую вероятные будущие позиции
```

Это пока рабочая гипотеза P12 и должна пройти Architect pass, Reality Check и Red Team / Falsification.

## 5. Граница Фазы 6

P12 в Фазе 3 определяет только **качественный профиль готовности**.

Сейчас не утверждаются:

- количество эпизодов;
- длительность периода наблюдения;
- проценты успешных случаев;
- числовые пороги;
- тесты и шкалы;
- процедура аттестации;
- точный допустимый объём внешней поддержки.

Эти элементы относятся к Фазе 6 согласно `TRANSITION_CRITERIA_BOUNDARY.md`.

## 6. Последний утверждённый архитектурный результат
