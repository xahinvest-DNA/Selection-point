# SP-SRC-026 — Выбор, исполнение, реализованный ход и обратная связь

**Дата:** 15 сентября 2026 года  
**Статус:** рабочий source material; не канон  
**Контекст:** сквозное уточнение ядра Selection Point до открытия SP-S5-P01

## 1. Owner insight

Андрей сформулировал критическое различение:

> **Сделанный внутренний выбор не означает совершённого действия, которое в реальности и даёт обратную связь.**

Рабочее следствие:

```text
внутренний выбор
≠ фактически совершённый ход
≠ последствия
≠ использованная обратная связь
```

## 2. Почему это важно

Selection Point уже различает:

```text
видеть
→ выбирать
→ действовать
→ получать последствия
→ использовать обратную связь
```

Но в языке `выбрать доступный ход` существует риск незаметно засчитать внутреннее решение как уже совершённый ход.

Пример:

```text
решил отправить предложение клиенту
→ испытал ясность / облегчение
→ предложение не отправил
```

Внутренний выбор действительно произошёл. Но внешняя гипотеза о реакции клиента не была проверена: клиент не получил предложение.

Фактически произошедшее продолжение — **неотправка** (или частичное исполнение, если, например, был создан черновик).

## 3. Рабочая цепочка

Кандидат на уточнение core cycle:

```text
фактическая позиция
→ доступная точка выбора
→ выбранное продолжение
→ исполнение / неисполнение / частичное исполнение
→ фактически реализованное продолжение
→ внешние и внутренние последствия
→ замеченные и интерпретированные данные
→ обратная связь
→ обновлённая позиция
```

Короткая формула:

> **Выбор создаёт возможность другой траектории. Реализованный ход участвует в создании другой фактической позиции.**

## 4. Важные границы

### 4.1. Внутренний выбор не является «ничем»

Он может изменить:

- внимание;
- эмоциональное состояние;
- субъективное напряжение;
- готовность;
- план;
- ожидания;
- последующее поле действий.

Поэтому нельзя утверждать, что выбор не имеет никаких последствий до внешнего действия.

Точнее:

> **Неисполненный выбор не даёт реального ответа на последствия того внешнего действия, которое не было совершено.**

Он может дать данные о самом выборе и о разрыве `выбор → исполнение`.

### 4.2. Бездействие может быть реализованным ходом

Если человек сознательно выбирает паузу, отказ, ожидание, невмешательство или удержание от действия и фактически это выдерживает, это является реализованным продолжением.

```text
выбрал не отправлять сообщение до утра
→ действительно не отправил
→ реальность продолжилась при выдержанной паузе
```

Это отличается от:

```text
выбрал отправить сообщение
→ не отправил
```

Во втором случае надо исследовать разрыв между выбором и исполнением.

### 4.3. Частичное исполнение даёт частичную проверку

```text
выбрал запустить проект
→ написал первый экран
→ не опубликовал
```

Есть реальные данные о способности начать / написать экран, но нет ответа рынка на несуществующий запуск.

### 4.4. Действие не гарантирует ясной обратной связи

Даже совершённый ход может иметь:

- задержанные последствия;
- шумный результат;
- несколько причин;
- неопределённую связь между действием и исходом.

Поэтому:

```text
совершил действие
≠ автоматически узнал истину
```

## 5. Связь с утверждённой архитектурой

### HCM general model

Уже содержит:

```text
доступная точка выбора
→ действие
→ последствия
→ обратная связь
```

### SP-HCM-05

Утверждает, что именно действие создаёт контакт между внутренней моделью и реальностью и добавляет новые фактические данные.

### SP-HCM-06

Уже различает последствия и использованную обратную связь.

### SP-HCM-07

Утверждает, что выбор может восстановиться после уже совершённого действия, что логически также требует различать выбор и действие.

### Protocol v4.1

Исследовательская последовательность уже записана как:

```text
допустить возможность
→ выбрать
→ действовать
→ дать реальности ответить
→ получить факт
→ скорректировать картину
```

и содержит формулу:

> **Действие — вопрос реальности. Ожидание — пространство для ответа. Факт — полученный ответ.**

Следовательно, owner insight не противоречит ядру, а выявляет boundary, который следует сделать более явным.

## 6. Рабочая диагностическая матрица

```text
выбрал + реализовал
→ проверяем совершённый ход и его последствия

выбрал + не реализовал
→ не приписываем feedback неисполненному ходу;
→ исследуем разрыв выбор → исполнение

не выбрал + автоматически реализовал
→ исследуем доступность Selection Point

выбрал невмешательство / паузу + выдержал
→ это реализованное продолжение;
→ исследуем его последствия
```

## 7. Связь с SP-S4-P13

P13 утверждает:

> **Выбор совершается в моменте. Траектория обнаруживается во времени.**

SP-SRC-026 добавляет рабочее уточнение:

> **Траектория во времени складывается из фактически реализованных продолжений, а не только из внутренне выбранных ходов.**

Поэтому можно многократно выбирать направление и при этом наблюдать иную фактическую траекторию, если выбранные ходы не исполняются.
