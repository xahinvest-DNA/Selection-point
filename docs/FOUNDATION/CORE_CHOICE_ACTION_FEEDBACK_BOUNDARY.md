# Core boundary — выбор, реализация, последствия и обратная связь

**Статус:** утверждённое сквозное фундаментальное уточнение  
**Дата утверждения:** 15 сентября 2026 года  
**Основание:** явное решение владельца после Architect pass → RC-018 → Red Team  
**Применяется к:** `ARCHITECTURAL_DECLARATION.md`, `HUMAN_CHANGE_MODEL.md`, canonical HCM, core cycle, SP-S4-P13 и будущей практической архитектуре

Этот документ является утверждённым addendum к фундаментальному слою Selection Point. Он не создаёт SP-HCM-10 и не меняет смысл уже утверждённых HCM-положений; он устраняет неоднозначность между внутренним выбором и фактически реализованным продолжением.

## 1. Центральное различение

> **Внутренне выбранное продолжение не равно фактически реализованному продолжению.**

```text
выбранное продолжение
≠ фактически реализованное продолжение
≠ последствия
≠ использованная обратная связь
```

Короткая формула:

> **Выбрать ≠ сделать. Сделать ≠ получить желаемое. Последствия ≠ автоматически использованная обратная связь.**

## 2. Почему это фундаментально

Selection Point восстанавливает способность выбора, но сам внутренний выбор ещё не гарантирует изменения внешней причинной цепочки.

Человек может:

```text
решить отправить предложение
→ испытать ясность / облегчение
→ не отправить предложение
```

Внутренний выбор действительно произошёл и может изменить внутреннее состояние. Но рынок не получил предложение, поэтому его отсутствие реакции нельзя считать feedback на неслучившееся действие.

Главная граница:

> **Внутренний выбор открывает другое возможное продолжение. В фактическую траекторию входит то продолжение, которое реально произошло.**

## 3. Уточнённый core cycle

```text
фактическая позиция
→ доступная точка выбора
→ выбранное продолжение
→ фактически реализованное продолжение
→ внешние и внутренние последствия
→ замеченные и интерпретированные данные
→ использованная обратная связь
→ корректировка
→ следующая фактическая позиция
```

Выбранное и реализованное продолжение могут совпасть или разойтись.

Разрыв между ними — данные о процессе исполнения, а не автоматическое доказательство слабости, саботажа или морального провала.

## 4. Выбранное продолжение

**Выбранное продолжение** — внутренне принятое решение о том, какое доступное продолжение человек намерен реализовать из текущей позиции.

Это реальный внутренний факт. Он может изменить:

- внимание;
- состояние;
- субъективное напряжение;
- готовность;
- ожидания;
- планирование;
- психологическую доступность следующих действий.

Но он сам по себе не доказывает исполнения.

## 5. Фактически реализованное продолжение

**Фактически реализованное продолжение** — то, что реально произошло и вошло в причинную историю следующей позиции.

Оно может быть:

- совершённым действием;
- частичным исполнением;
- сознательно выдержанной паузой;
- сознательным отказом;
- невмешательством;
- автоматическим действием, отличным от выбранного;
- фактическим неисполнением выбранного действия;
- сознательным пересмотром решения после появления новых фактов.

Следовательно:

```text
realized continuation
≠ обязательно активное моторное действие
```

## 6. Разрыв выбор → реализация

```text
selected continuation = X
realized continuation = Y / partial X / non-execution
```

Сам факт несовпадения не объясняет причину.

Возможные объяснения:

- автоматизм;
- изменение состояния;
- забывание;
- конфликт приоритетов;
- объективное ограничение;
- новые факты;
- недостаток навыка;
- плохая организация исполнения;
- рациональный пересмотр решения;
- внешнее вмешательство.

Поэтому:

> **selected ≠ realized — это сначала наблюдаемый факт, а уже затем предмет исследования.**

## 7. Что именно проверяет реальность

Если выбранное действие не было совершено, нельзя приписывать ему внешние последствия как будто оно произошло.

```text
выбрал позвонить клиенту
→ не позвонил
```

Нельзя заключить:

> «звонок не сработал».

Реальность дала другие данные:

- решение было принято;
- звонок не состоялся;
- позиция продолжилась без звонка;
- могли проявиться причины разрыва исполнения.

## 8. Частичное исполнение

Частично реализованный ход даёт данные только в пределах реально совершённой части.

```text
выбрал запустить продукт
→ сделал лендинг
→ не открыл продажи
```

Есть feedback о создании лендинга и процессе исполнения. Нет market feedback о запуске продаж, которого не было.

> **Не расширять область проверки дальше фактически реализованной части.**

## 9. Действие не гарантирует желаемого результата

```text
выбрал X
→ сделал X
→ получил Y
```

Это не означает автоматически:

- что X был ошибкой;
- что X был правильным;
- что Y вызван только X;
- что один исход достаточен для вывода.

В реальности возможны:

- задержанные последствия;
- шум;
- несколько причин;
- вероятностные исходы;
- влияние внешних условий.

Поэтому:

> **Реализованный ход делает ответ реальности возможным, но не гарантирует однозначного causal feedback.**

## 10. Последствия ≠ использованная обратная связь

Эта граница уже утверждена в SP-HCM-06 и сохраняется:

```text
реализованное продолжение
→ последствия
→ что замечено
→ как интерпретировано
→ какой вывод сделан
→ что изменено в следующем цикле
```

Обратной связью для Selection Point последствия становятся тогда, когда реально способны скорректировать модель, действие или условия следующего цикла.

## 11. Связь с SP-S4-P13

SP-S4-P13 утверждает:

> **Выбор совершается в моменте. Траектория обнаруживается во времени.**

RC-018 уточняет:

> **Фактическая траектория во времени складывается из реально произошедших продолжений и их последствий, а не только из серии внутренних выборов.**

Например:

```text
14 дней:
14 раз выбрал работать над проектом
2 раза реально работал
```

Серия внутренних выборов показывает сохраняющееся направление намерения.

Серия реализованных продолжений показывает фактическую поведенческую траекторию.

Разрыв между ними — часть текущей реальности.

## 12. Диагностическая матрица

```text
выбрал + реализовал
→ исследуем ход, последствия и feedback

выбрал + не реализовал
→ не приписываем feedback неисполненному ходу
→ исследуем разрыв выбор → реализация

не выбрал + автоматизм реализовался
→ исследуем доступность Selection Point

выбрал паузу / невмешательство + выдержал
→ это реализованное продолжение
→ исследуем его последствия

выбрал + частично реализовал
→ учитываем только фактически проверенную часть
```

## 13. Обязательные защиты

```text
internal choice = real event
≠ proof of execution

selected ≠ realized
≠ automatically sabotage / weak will

non-action
may be intentional realized continuation

partial execution
→ partial test

action
≠ guaranteed desired outcome
≠ guaranteed causal clarity

consequences
≠ automatically used feedback
```

## 14. Архитектурные следствия

1. Core cycle обязан различать выбранное и реализованное продолжение.
2. В будущей Phase 5 практическая фиксация должна задавать раздельно как минимум:
   - что было выбрано;
   - что фактически произошло;
   - где они совпали / разошлись;
   - какие последствия относятся к реально произошедшему;
   - что стало feedback для следующего цикла.
3. P13 не переписывается; новое различение уточняет чтение фактической траектории.
4. Новый SP-HCM-10 не создаётся.
5. SP-S5-P01 этим решением не открывается.

## 15. Итоговая формула

> **Selection Point открывает возможность другого продолжения, но внутренний выбор не засчитывается как реализованный ход. Фактическую траекторию формирует то продолжение, которое реально произошло; его последствия дают данные, а обратной связью эти данные становятся только тогда, когда способны изменить следующий цикл.**
