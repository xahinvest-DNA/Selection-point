## 4. SP-S3-P08 — утверждённое положение

Полный источник:

- `docs/FOUNDATION/FIVE_STAGES_THEORY/34_STAGE_3_NEXT_SKILL.md`.

Канонический источник:

- `docs/FOUNDATION/CANONICAL/26_STAGE_3_P08_CANONICAL.md`.

Рабочее название:

> **«Сохранять без упрямства, менять без бегства».**

Центральный тезис:

> **Следующий навык третьей ступени состоит в способности вести сознательно выбранную внутреннюю задачу через повторяющиеся циклы действия и обратной связи: сохранять или восстанавливать её управляющее присутствие, когда основания задачи сохраняются, и уточнять или менять её, когда фактическая следующая позиция даёт существенные основания для пересмотра.**

Короткая формула:

> **Сохранять без упрямства, менять без бегства.**

Формула опоры на себя:

> **Опора на себя — не гарантия, что я не изменю своё решение. Это способность снова участвовать в том, сохранить его или изменить.**

## 6. Три объекта возможной корректировки

P08 различает:

```text
1. управляющее присутствие задачи
2. способ решения задачи
3. сама задача
```

Контур:

```text
задача B
→ действие / бездействие
→ ответ среды
→ фактическая следующая позиция
→ обратная связь

→ B обоснована и сохраняет приоритет
  → продолжить

→ B обоснована, но потеряла приоритет
  → восстановить B

→ B обоснована, но способ не работает
  → изменить способ

→ накопленные данные подрывают основания B
  → уточнить или изменить B
```

---

## 7. Уточнение устойчивости

> **Устойчивость — способность сохранять выбранную организацию достаточно долго, чтобы получить реальную обратную связь, и одновременно оставаться способным изменить её, когда накопленные данные дают основания для пересмотра.**

Две симметричные ошибки:

```text
слишком быстро менять задачу
→ она не проходит реальную проверку

никогда не менять задачу
→ обратная связь перестаёт иметь значение
```

P08 не задаёт числовой или процедурный критерий «достаточно долго».

---

## 8. Центральные границы

```text
обратная связь
= данные для следующего выбора
≠ внешний приказ
```

```text
негативный результат одного цикла
≠ автоматическое опровержение задачи
```

```text
положительный результат одного цикла
≠ доказательство полезности задачи
```

```text
изменить способ
≠ обязательно изменить задачу
```

```text
изменить задачу по достаточной обратной связи
≠ потерять авторство
```

Selection Point не определяет человеку универсально правильную жизнь или полезную задачу.

## 9. Новое обязательное правило трёх вопросов

Перед содержательным открытием каждого следующего архитектурного пункта:

```text
предыдущий пункт утверждён и синхронизирован
→ следующий пункт остаётся не открытым
→ ChatGPT задаёт ровно 3 вопроса Андрею
→ вопросы обсуждаются
→ только затем открывается следующий пункт
```

Требования:

- вопросы должны относиться к реальному архитектурному противоречию следующего пункта;
- не навязывать готовый ответ;
- хотя бы один вопрос должен проверять границу или риск;
- опираться на уже утверждённую архитектуру;
- не заменяться готовым разбором следующего параметра.

Правило действует до его явного изменения Андреем.
