# Selection Point — Adaptive Environment Architecture V0

**ID:** SP-AEA-001  
**Status:** approved_direction_working_architecture  
**Approved direction:** 3 November 2026  
**Validation status:** unvalidated  
**Role:** active product architecture for the environment-first route.

## 1. Product object

Selection Point V0 is not primarily a course, lesson sequence, coach or advice engine.

It is a **bounded adaptive environment** in which the participant repeatedly encounters situations where a practically available choice can emerge, disappear, be restored, be acted on or remain unrealized.

The environment is designed to make consequential distinctions experientially available rather than merely explain them.

The product must therefore create repeated contact with:

```text
position
-> relevant signals and constraints
-> Selection Point
-> available continuations
-> selected continuation
-> realized / partially realized / consciously not acted / not realized continuation
-> consequences
-> feedback
-> changed next position
```

## 2. Change hypothesis

Working hypothesis:

> A capacity for selection is more likely to become practically available when a person repeatedly experiences representative choice situations, acts within them, sees consequences and receives feedback under varied conditions, than when the same distinctions are only explained as knowledge.

This is a hypothesis to be tested, not a claim of guaranteed human change.

The environment is not expected to “install” a correct answer. It should improve the participant's capacity to notice relevant structure, preserve a direction while changing route, distinguish intention from realization, and use feedback from consequences.

## 3. Two coupled loops

### 3.1 Simulation Loop

```text
Scenario state
-> perception cues
-> Selection Point
-> continuation options
-> participant selection
-> simulated realization / non-realization
-> immediate consequence
-> delayed / trajectory consequence where applicable
-> next varied scenario
```

The simulator can compress time so that repeated local decisions reveal a longer trajectory that ordinary life exposes only slowly.

### 3.2 Reality Transfer Loop

```text
pattern experienced in simulation
-> bounded real-world experiment
-> factual record of what was realized
-> consequences / contradictions / missing information
-> review
-> next scenario or changed scenario parameters
```

The Reality Transfer Loop is not homework attached to a lesson. It is the empirical boundary that prevents the simulator from becoming a self-contained game whose skill does not transfer.

## 4. Scenario design rules

Every active scenario should satisfy the following rules.

### 4.1 Representative structure over visual realism

Preserve the information that should matter for the decision and the relationship between perceived information, available action and consequence. High visual immersion is optional.

### 4.2 No moralized answer key

Alternatives must be plausible from the participant's current position. The environment should not disguise a quiz where one answer is obviously the author's preferred answer.

### 4.3 Consequences, not lectures, carry the main signal

The primary feedback is what the continuation changes in the next position and trajectory. Explanatory text is secondary.

### 4.4 Repetition without identical repetition

Keep the underlying structure while varying context, load, timing, social pressure, fatigue, uncertainty, competing rewards or other relevant constraints. The participant should learn the structure, not memorize a response.

### 4.5 Multiple time scales

Where the capability requires it, show the distinction between a locally reasonable move and its repeated trajectory effect across day/week/month or another relevant scale.

### 4.6 Selected is not realized

A scenario must be able to represent the difference between:
- what a participant selected;
- what was actually realized;
- what was partially realized;
- what was consciously not acted on;
- what failed to be realized without a new conscious choice.

### 4.7 Prompt fading

If scaffolds are used, they should be reduced over repeated situations. Persistent dependence on a prompt is not mastery.

### 4.8 Theory follows experience when possible

A project term may name a distinction after the participant has encountered it. Vocabulary should not be mistaken for capacity.

### 4.9 Preserve agency

The system may expose consequences and contradictions but should not coerce a preferred identity, diagnose the participant, or present the author's route as universally correct.

## 5. V0 scope

V0 is deliberately constrained to prevent another architecture-expansion cycle.

### Required

- one target capability;
- one observable domain: effective body / physical efficiency;
- 10–15 manually authored representative scenarios;
- at least one repeated structural pattern across several surface variants;
- at least one trajectory/time-scale consequence;
- one real-world transfer experiment;
- factual distinction between selected and realized continuation;
- post-experience debrief sufficient to capture contradictions and transfer evidence.

### Not required

- mobile application;
- VR/AR;
- AI-generated scenarios;
- adaptive personalization engine;
- full five-stage curriculum;
- scoring system;
- gamification economy;
- social layer;
- automated prediction;
- external-user pilot before explicit authorization.

Manual delivery is acceptable if it tests the mechanism faster and more cleanly.

## 7. Measurement and evidence boundary

Do not infer transfer from:
- completing scenarios;
- selecting the preferred continuation;
- understanding project vocabulary;
- self-reported insight;
- high engagement;
- repeated simulator success alone.

Relevant evidence can include:
- earlier recognition of the same structure under changed conditions;
- reduced dependence on prompts;
- ability to preserve direction while changing route;
- clearer distinction between selected and realized continuation;
- a changed real-world action in a representative situation;
- use of real consequences to revise the next move;
- failure cases and regressions.

All real-world evidence keeps fact, self-report and interpretation separate.

## 8. Falsification conditions

The V0 hypothesis is weakened if one or more of the following persists:

1. participants learn to optimize simulator answers but do not transfer the distinction into real situations;
2. success requires repeated explanation by an external leader;
3. scenarios become obvious quizzes with socially desirable answers;
4. a change appears only while prompts are present;
5. simulated consequences are too arbitrary to be experienced as credible structure;
6. the environment cannot distinguish intention from realization;
7. the product requires a large platform before the core mechanism can be tested;
8. the participant becomes better at project vocabulary without a corresponding practical difference.

## 9. Scientific boundary

The architecture does not assume that imagined, simulated and real experience are neurologically identical.

The working scientific position is intentionally narrower:
- imagery/simulation can support learning in some contexts;
- more immersion is not automatically more transfer;
- representative perceptual information and decision structure can matter strongly;
- real-world transfer must be tested directly.

## 10. Next design object

The next artifact is not a Lesson 1 and not a software specification.

It is a definition of:

1. **one V0 capability** that must become more practically available;
2. the **scenario grammar** that can repeatedly expose this capability under varied constraints;
3. the minimum observable evidence that differentiates simulator learning from real-world transfer.

Until this is reviewed, do not expand V0 into additional capabilities, stages or interface features.
