# Stage 1 Practice Protocol — Execution Contract

**ID:** SP-TR-S1-PP-SPEC-001  
**Gate:** E — Practice Protocol  
**Status:** active  
**Date:** 19 September 2026  
**Upstream capability:** `SP-TR-S1-CAP-002`  
**Upstream Learning Units:** `SP-TR-S1-LU-001`  
**Gate D decision:** `SP-TR-DEC-S1-D-001`

## 1. Purpose

Gate E must define how Stage 1 is actually practiced in real life so that the learner can train:

```text
NOTICE → OPEN → REALIZE → UPDATE
```

while preserving the longer direction:

```text
repeated useful cycles
→ lower-load retrieval
→ possible useful automaticity
with selective interruptibility preserved
```

Gate E may define practice forms, practice sequence, entry conditions, support/scaffold use and repetition logic.

Gate E must **not** define validated mastery thresholds, scoring, final measurement instruments, software implementation or external-pilot claims. Those belong to later gates.

## 2. Central protocol question

> **What is the smallest real-life practice architecture that repeatedly creates genuine opportunities to notice, reopen, realize and reality-update without turning the learner into a permanent observer of themselves?**

## 3. Required practice functions

The protocol must provide practical ways to train all four Learning Units.

### E1 — NOTICE practice
Train selective detection of a relevant current event/cue without exhaustive self-monitoring.

### E2 — OPEN practice
Train a small, usable interruption window when there is meaningful mismatch.

### E3 — REALIZE practice
Train one concrete executable alternative, including prepared alternatives where useful.

### E4 — UPDATE practice
Train factual return to consequence/current position without causal overclaim.

### E5 — Cross-cycle repetition
Provide a way for useful continuations to recur often enough to test whether retrieval/execution becomes easier, while not defining a universal repetition threshold.

### E6 — Late-entry practice
Allow training after the main automatic action has already occurred: stopping escalation, repair, consequence reduction, support-seeking, or next-cycle preparation.

## 4. Scaffold architecture

Gate E may use temporary external supports such as:

- reminders;
- evening review/questionnaire;
- prospective cueing;
- environmental cues;
- if–then plans;
- prepared substitute actions;
- trainer/AI prompts.

But every protocol element must make support provenance visible.

Minimum provenance classes:

```text
A — externally prompted
B — anticipatory scaffold-linked
C — participant-initiated
```

These are not mastery levels and must not be scored in Gate E.

## 5. Measurement-reactivity boundary

Because questionnaire exposure may itself alter attention/behavior:

```text
questionnaire completion ≠ SP proof
questionnaire data = telemetry
questionnaire exposure may be intervention/scaffold
```

Gate E may intentionally use this reactivity as a training hypothesis, but must not hide it.

Gate E should distinguish where possible:

- recall-only reporting;
- in-the-moment noticing linked to future reporting;
- behavior changed because reporting was anticipated;
- participant-initiated noticing/action without identifiable current scaffold activation.

No causal conclusion is permitted from one route alone.

## 6. Interruption boundary

The protocol must not train generic pausing or inhibition as virtue.

```text
automaticity
≠
interruption required
```

Interruption practice is relevant only when a meaningful mismatch is present or deliberately simulated for training.

Candidate intervention classes may include:

- pause/delay;
- context shift;
- cue removal/change;
- competing response;
- prepared if–then response;
- support-seeking;
- stopping/reducing an already-started continuation.

No single class is assumed universal.

## 7. Replacement boundary

A protocol that only stops the old route is incomplete.

```text
interruption
≠
replacement
```

Where possible, practice should pair the interruption window with one executable continuation.

The continuation must remain:

- reality-anchored;
- locally relevant;
- safe;
- participant-owned;
- revisable after new facts.

## 8. Automaticity boundary

Gate E may train repetition toward easier retrieval/execution.

It must not assume:

- old learning is erased;
- one or several successes equal a new habit;
- a fixed number of days produces automaticity;
- a new automatic response remains useful forever.

The intended long-term pattern remains:

> **efficient default + reopenability under meaningful mismatch.**

## 9. Learner-load rule

The learner should not carry the full designer architecture during the event.

Candidate live compression:

> **Заметь → открой → сделай → сверься.**

Practice may train components separately before integrating them.

The protocol should prefer operational simplicity under load.

## 10. Practice-layer outputs expected from Gate E

The final Practice Protocol should define, at minimum:

1. practice modes for each Learning Unit;
2. how a practice opportunity is selected or recognized;
3. what the learner actually does in the moment;
4. what may be prepared in advance;
5. what is recorded afterward;
6. how late-entry practice works;
7. how external prompts/scaffolds are labeled;
8. how repetition is structured without declaring mastery thresholds;
9. how lapse/old-route return is handled;
10. when the protocol should route to external/professional support;
11. what counts as protocol completion for an episode;
12. what remains for Gate F measurement rather than Gate E.

## 11. Required Red Team attacks

Gate E Red Team must explicitly test:

- Does the protocol create hypervigilance/self-monitoring?
- Does it turn every automatic action into a problem?
- Does it over-rely on willpower at peak impulse?
- Does it confuse reminder compliance with capacity?
- Does it create dependence on questionnaire/AI?
- Does it reward reportability rather than reality improvement?
- Does it force a pause when skilled automaticity should remain uninterrupted?
- Does it treat one alternative as permanently correct?
- Does it smuggle causal archaeology back into review?
- Does it punish lapses instead of treating them as new data/re-entry points?
- Does it require Stage 2–4 capacities?
- Is the practice actually executable in ordinary life?

## 12. Non-goals

Gate E must not produce:

- validated scoring;
- numeric mastery thresholds;
- final Selection Capacity metric;
- diagnostic labels;
- final questionnaire validation;
- software/UI implementation;
- external-user pilot authorization;
- Stage 2 curriculum;
- Foundation canon changes.

## 13. Completion criterion

Gate E is ready for Owner review when:

- every Learning Unit has a practical training form;
- the integrated practice can be executed in ordinary life;
- interruption is selective rather than compulsive;
- realization is factual, not intentional;
- consequence/update is reality-coupled;
- scaffold effects remain visible;
- repetition supports possible re-automatization without claiming it;
- late-entry and lapse/recovery are first-class;
- learner load remains low;
- Red Team passes with constraints;
- Gate F remains closed until explicit Owner approval.
