## Active environment-first route

The former course-first route is superseded as active development. The current route is deliberately shorter and must not silently expand.

### E0 — Direction reset — COMPLETE

- environment-first product hypothesis approved;
- course-first marked historical/reference;
- scientific transfer boundary recorded;
- Foundation canon left unchanged.

### E1 — Define one V0 capability — CURRENT

Define one practically available capability/distinction to train in the first environment slice.

Exit condition:
- capability is observable enough to design scenarios and transfer evidence;
- it is not merely project vocabulary;
- it fits the effective-body field without reducing the method to health.

### E2 — Define scenario grammar

Specify the invariant structure of a representative scenario and which conditions may vary.

Exit condition:
- 10–15 scenarios can be authored without becoming disguised quizzes;
- selected and realized continuation remain distinct;
- delayed/trajectory consequences can be represented where relevant.

### E3 — Build the minimum environment manually

Use the simplest delivery capable of testing the mechanism. Software, VR, AI and platform work remain optional and closed unless separately approved.

Exit condition:
- participant can complete the scenario loop;
- prompts can fade;
- simulator observations can be recorded without claiming real-world transfer.

### E4 — Reality Transfer Loop

Run one bounded real-world experiment after the simulation exposure.

Exit condition:
- factual realization/non-realization is recorded;
- consequences and contradictions are captured;
- simulation performance is compared with real behaviour without collapsing the two.

### E5 — Owner review / falsification

Owner chooses one of:
- approve another bounded V0 iteration;
- revise capability/scenario grammar;
- reject or weaken the environment-first hypothesis;
- authorize a later implementation or external pilot.

No next phase opens automatically.
