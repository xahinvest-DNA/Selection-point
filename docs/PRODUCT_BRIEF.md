## Product in one sentence

Selection Point is a bounded adaptive environment in which a person repeatedly encounters representative situations, selects a continuation, experiences consequences and feedback, and then tests whether the acquired distinction transfers into real behaviour.

## Problem

A person can know what they want, understand useful advice and even make a sincere decision in advance, yet lose practical access to that choice when fatigue, stress, reward, social pressure, uncertainty or automatic behaviour changes the current position.

The product therefore does not assume that more explanation is the missing ingredient.

## Product mechanism

```text
representative situation
→ position / constraints
→ Selection Point
→ plausible continuations
→ selection
→ realized / non-realized continuation
→ immediate + delayed consequences
→ feedback
→ changed next situation
→ repeated experience under variation
```

Validation adds:

```text
simulation experience
→ bounded real-world experiment
→ factual realization / non-realization
→ real consequence
→ review
→ next iteration
```

## What makes it Selection Point

The environment should make the participant repeatedly encounter and practically discriminate:
- current position rather than abstract intention;
- direction versus route versus immediate action;
- automatic continuation versus available alternative;
- selected continuation versus realized continuation;
- local consequence versus trajectory consequence;
- feedback that changes the next move.

The system should not teach these only as definitions. They should exist as mechanics of the experience.

## First field

**Effective body / physical efficiency** remains the first observable field because it provides frequent situations, visible actions and consequences. This does not define the full boundary of Selection Point.

## V0

V0 is intentionally constrained:
- one target capability;
- 10–15 representative scenarios;
- one repeated structural pattern under varied conditions;
- at least one meaningful multi-scale consequence;
- one real-world transfer experiment;
- manual/simple delivery allowed.

Not required for V0:
- mobile app;
- VR/AR;
- AI agent;
- automatic scenario generation;
- full Stage 1 course;
- scoring/gamification economy;
- social features;
- predictive engine.

## Experience principle

The primary signal should come from **consequences and trajectory**, not from the system declaring an answer correct.

Alternatives must remain plausible from the participant's current position. A scenario that can be solved by guessing what the author wants is weak training evidence.

## Theory and language

Theory is secondary support. When useful, it names a distinction after or around experience. Knowing the term is not evidence that the capability became practically available.

## Evidence

Relevant evidence includes:
- recognition under changed conditions;
- reduced prompt dependence;
- route change without abandoning direction;
- selected-versus-realized discrimination;
- changed real action in a representative situation;
- feedback used in the next move;
- regressions, failures and contradictions.

Simulator success alone is not transfer evidence.

## Scientific boundary

The product does not rely on the statement that the brain treats imagined/simulated and real events as identical. The working hypothesis is only that simulated practice can support learning when relevant structure is preserved, while real-world transfer must be measured independently.
